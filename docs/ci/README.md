# Turning on CI (owner action, ~2 minutes)

The repo has no automated validation on pull requests. AGENTS.md §2 rule 2 says
the reason is that the GitHub App the agent harnesses use cannot write to
`.github/workflows/`. **A human with admin rights can.** Once the workflow is on
the remote, every PR from every harness gets `validate.py`, the vocabulary check,
the tests and the SQLite build run automatically. AGENTS.md says campaign mode
gets revisited "if Workflows permission is ever granted and the workflow lands on
the remote".

Steps:

1. On github.com open the repo → **Add file → Create new file**.
2. Name it `.github/workflows/validate.yml` and paste in the contents of
   [`docs/ci/validate.yml`](validate.yml).
3. Commit straight to `main`. This is your own push, not an agent's.
4. Optional: Settings → Branches → add a protection rule for `main` that
   requires the `validate` check. Agents' PRs then cannot merge red.

Then run a dated AGENTS.md revision for §2 rule 2 (campaign mode). That revision
is an owner ruling, so no agent self-rules it.

Runtime: about 30 s on GitHub's free runners. Everything is stdlib Python, with
nothing to install.

# Publishing to GitHub Pages (owner action, ~3 minutes)

The repo is public, so Pages is free. Once these steps are done, the site lives
at **https://polymerindustrycluster.github.io/polymer-atlas/** and rebuilds itself
on every push to `main`.
- **What is published:** the static site (home, map, search, Ohio county pages,
  one page per organization) plus the three explorers (`graph/index.html`,
  `graph/map.html`, `graph/events.html`).
- **What it is built from:** everything is generated by `scripts/build_pages.py`
  from the canonical CSVs, with public fields only.
- **What is committed:** nothing generated; `build/` stays gitignored.

Steps:

1. On github.com open the repo → **Add file → Create new file**.
2. Name it `.github/workflows/pages.yml` and paste in the contents of
   [`docs/ci/pages.yml`](pages.yml). Commit straight to `main`.
3. Open **Settings → Pages**. Under **Build and deployment → Source**, choose
   **GitHub Actions**. Leave the branch fields empty.
4. Open **Actions → pages → Run workflow**, or push anything to `main`.
   - The first deploy takes about a minute.
   - The site URL then appears on the run and under Settings → Pages.

Notes:
- **Validation gate:** the workflow runs `scripts/validate.py` first. A red data
  tree is never published, and the last good site stays up.
- **Scripts must be on `main`:** `scripts/build_pages.py` and the graph builders
  have to be there first. If they are still in an open PR, merge it before step 4.
- **Preview locally:**
  `python3 scripts/build_pages.py && python3 -m http.server -d build/pages 8000`,
  then open http://localhost:8000.
- **Turning it off:** Settings → Pages → Unpublish, or delete the workflow file.
