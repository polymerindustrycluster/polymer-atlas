# How the Atlas finds, proves and captures websites, addresses and pages

Written 2026-11-24 on main at `6e2229ab`. This page records the tools and routes the Atlas uses to find company
websites, street addresses, LinkedIn and press links, and page content. It also records what each experiment tried and
what it yielded. `docs/SOURCES.md` and `docs/sources_registry.csv` record data sources. `docs/IDEAS_AND_RESOURCES.md`
records ideas. This page records the acquisition stack and its test results.

How to read the numbers. Every count names its unit and its filter (AGENTS.md §7). Frames differ between rows. A
blank-street count of 155 sites is the base of the 2026-11-24 street packets. The 153 in section 5 is main today, after
two street fills. A count of 794 owners (2026-11-23) and 792 (today) differ because two sites moved to tier U and their
owners left the frame (DECISIONS.md). This page does not reconcile other bases. Each row says which base it uses.

An owner, in the PIC-18 counts below, is an organization record or an ecosystem record with at least one active tier A,
B or C site in the 18 PIC-18 counties (AGENTS.md §8). Today that is 785 organization records and 7 ecosystem records.

is recorded only after a fetched page shows the held name and an Ohio locality" was not found in AGENTS.md, SCHEMA,
DECISIONS.md or the owner-ruling folders. The 2026-11-04 website pass was national and required the full name and a
polymer term, not an Ohio place. The Ohio locality test exists only as the binding gate's street and city checks on
own-site address rows. "LinkedIn URLs come from search only" was not found either. The ruling says navigation only,
and the passes took the links from the company's own pages.

## 2. The stack today

| Tool or route | What it does | Where it lives | Allowed to support | Known limits |
|---|---|---|---|---|
| Own-site corpus crawler | Fetches a company's home page, sitemap and up to one page per kind (about, locations, news, quality, markets, products). Caches raw bytes, a text copy, a SHA-256 and a receipt per URL. Uses curl first and falls back to Jina Reader. | `scripts/site_corpus.py` (`crawl`, `rawcheck`). Declared user agent `Mozilla/5.0 (compatible; AtlasSiteCorpus/1.0)`. Robots checked on every hop. At least 1 second per host, Retry-After honored. The raw cache sits on the controller machine, outside the repo, not on the NAS. The code refuses a cache inside the repo. | Navigation links, parent, capability and market leads, and quotes that a binding proof then replays | Reads static HTML text only. A page that needs JavaScript to render shows as thin or empty. A robots refusal is recorded as `ROBOTS_BLOCKED` and stays held. One page per kind, picked by URL path words, so it can miss the right page. |
| Binding gate and proof replay | Judges each evidence row for name, street and locality binding, by record table and claim type. Replays a proof capture by hash and quote offset (`capture_text()`). Reads git refs, runs nothing from the PR tree. | `scripts/check_evidence_binding.py`, run as the `binding-gate` check of `pr-rules` | Admission of structured and own-site web rows. PASS is a minimum, not a verdict. | Does not sample or read pages, and does not replay a packet. Registry links and people rows are outside it. Tests differ by record table and claim type (section 1). |
| Street and locality matcher | `same_street()` compares normalized street keys plus suite and building designators. `same_locality()` compares state, city and ZIP5. | `scripts/matching.py` | The street and city legs of the gate, the map-listing route and the filing name variant | Strict by design. It misses ranges, number words and a quoted number inside a recorded range. A blank street never matches. |
| Dedupe check | Runs the AGENTS.md §3 steps in order: domain, normalized name, street, trade names and successors, site names. Also allocates IDs above the tree-wide maximum. | `python3 scripts/atlas.py dedupe-check`, `next-id`, `show` | Nothing. It prevents duplicate records. | Misses a street that sits only in site notes. One lane found a duplicate this way and the create was withdrawn. |
| Direct fetch with a browser user agent | Plain curl with a browser user agent, with a one-retry transport policy and a global request pool. | Task scripts such as `tasks/pic18-fetch-retry-2026-11-06/` and `tasks/archive-topup-1-2026-11-06/` | Quote presence on a cited page | Some sites refuse a declared crawler and accept a browser string. That is a different declared posture from the corpus crawler. |
| Jina Reader | Returns a text version of a page by URL. Used for the first website pass on 2026-11-04 and as the corpus crawler's fallback. | A hosted service, called from task scripts and `scripts/site_corpus.py` | Leads and quote checks | On 2026-11-20 it answered HTTP 402 (out of credit), so every failed direct fetch in that pilot stayed failed. The corpus crawler accepts a Jina result only if its "URL Source" header names the same page. A wrapper that reports an upstream 404 counts as a failed fetch. |
| Self-hosted Firecrawl (NAS) | Scrapes one URL to rendered HTML, markdown or PDF text. Used for roster pages rendered on 2026-11-04 and for the failed-fetch retry of 2026-11-06 (live fetch, `maxAge` 0). | Project-operated service on the NAS, reached through its MCP server | Quote presence and roster reading | One scrape worker, so calls serialize. No cloud AI, no browser actions, no screenshots, no private-network URLs. It returned HTTP 502 on 2026-11-20. Its PDF text joined table cells into single words, which blocked 10 quotes from a matching PDF. |
| Self-hosted SearXNG (NAS) | Metasearch. Used for candidate-URL discovery (the 2026-11-06 source-scout lanes recorded each search) and for LinkedIn dorking in the people test. | Project-operated service, reached through its MCP server | Leads only | The search result is a lead. The own page it points to must then be fetched and bound. |
| Serper (Google results API) | One query per organization, `"<legal name>" <city> <state>`, to find an own-domain website. Used once, on 2026-11-04. | Task script `tasks/websites-2026-11-04/search.py` | A candidate URL, accepted only through the 6 gates in section 1 | Paid. No later pass used it. |
| Real Chrome through local Playwright | Renders pages that a plain fetch cannot read. Used for 4 of 10 exhibitor rosters on 2026-11-06. | Task script `tasks/exhibitor-links-2026-11-04/fetch_rosters.py` | Organization names on a roster, under the owner's roster ruling | Used for rosters only. The 2026-11-24 refetch pilot rendered apparent script shells with Playwright Chromium: 13 of 14 renders came back thin, and no owner gained a value (section 4). |
| Wayback Machine, CDX and Save Page Now | CDX finds an existing capture. Save Page Now makes a new one. A capture is admitted only if it replays with HTTP 200 and holds the preserved quote. | Task scripts under `tasks/archive-topup-*` and `tasks/evidence-backfill-url-pilot-2026-11-20/`. A capture within the two-year window may also stand in for a live page (SCHEMA §4.13). | Rate limits: the first discovery run hit sustained HTTP 429 after about 100 responses. Never evidence. | Only exact matches fill. Non-exact and tied results are held. County differences are held for a physical-address source. |

## 6. How to keep this page current

Append one row to the experiments log in the same PR as any new acquisition experiment: a new fetch route, a new search
or map source, a new reader or matcher test, or a new link or address pass. Name the unit and filter in the frame and
yield cells. If the experiment adds a tool or route, add a row to section 2. If it drops one, add a row to section 4.
Run `python3 tasks/acquisition-record-2026-11-24/check.py` before the PR. It fails when a row names a folder or file that
does not exist, or a controller packet it does not know. Add a new packet name to the check at the same time. A new data
source also gets its own registry row (standing rule 2026-11-21).
