Acceptance checks

- A structured quote for a supported claim can bind to a program or ecosystem
  record. A quote naming another record or placing it in another city or state
  cannot pass. Claim classes without a binding test remain UNINSPECTABLE.
- Own-site evidence goes through the per-row proof and capture replay. A
  Divi-style body wrapper can yield usable text while an empty or chrome-only
  capture cannot replay a quote.
- Run the planted cases on the original gate and the patched gate. Count verdicts
  from both versions on the same pinned main tree and reconcile the evidence IDs.

## Gate behavior

Structured existence, scope and address claims use the organization gate's
held-name and parent-name rules. The checks use the program name or the
ecosystem entity's own name, including its named office when present. A
structured address claim needs an entity-address source. Where a structured
quote carries an address, or a web row claims an address, its locality must
match the record's city and state. Quotes whose address cannot be parsed stay
UNINSPECTABLE. Other claim types stay UNINSPECTABLE except for own-site
activity, which uses the existing proof path.

Programs and offices use their recorded program or office page for
own-site proofs. Matching the host, path and query keeps a sibling page
on a campus website from substituting for the record's page. Ecosystem
institutions use the organization domain check. All three replay the
per-row proof against the captured bytes.

The extractor ignores header-style class and ID labels on the document
wrappers. If normalized main text is empty, it uses the remaining text
after excluding page chrome. A chrome-only capture still cannot replay a
quote.
