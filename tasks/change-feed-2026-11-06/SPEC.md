# C-04 change feed — acceptance before implementation

Controller assignment: one tooling PR on agent/codex/change-feed, from main97ee6bc. No canonical data changes or new schema/ID allocations. First users: PIC staff and EDO readers following Atlas changes; non-use review2026-12-06.

Generate build/changelog/CHANGELOG.md and Atom feed.xml from full main history (local main ref, default origin/main). First-parent net diffs are attributed to regular merge PRs and squash PR subjects; direct historical main commits are labelled as commits, never invented PRs. Branch-only commits are excluded. Root data imports are reported as initial rows. Shards are unioned by immutable key; unique organization/ecosystem transfers, reordering, CRLF and shard migrations do not create entities. Early history has simultaneous ORG-ID collisions across organizations/ecosystem; those table-specific rows stay distinct, and cross-table transfer matching requires uniqueness on both sides (AGENTS §3: avoid false merges). Restored, previously seen keys are labelled separately from first-time creations. Registry/person links use table-grain composite keys; archive links use their one-per-evidence-id key. Evidence is counted by record_table and is not duplicated in entity creation lists. Inclusion_log and generated *_all exports are excluded, explicitly.

Outputs list record IDs created, existing-key status/verification-tier changes (including blank transitions) and new evidence row counts by target table, with units. No notes, source/claim text, names, addresses, commit messages, authors or private/CRM content is published. IDs and controlled statuses/tiers only; unknown legacy controlled values are labelled unrecognized rather than copied. Counts are rows/changes, not companies or operational impact. Feed entry IDs/dates are stable from commit metadata; XML escaped; deterministic replay.

Named check: throwaway Git repository unittest covering merge+feature commits, squash and direct main history; three known outcomes (creation/status/tier+evidence), shard/ecosystem moves and formatting, composite key grain, privacy injection, malformed/duplicate input and shallow-history refusal. Full scripts pytest and validate0 before push; run actual main history and inspect nonempty outputs, deterministic hashes and key-count reconciliation. Two independent Codex+Grok completion refutes required. No Pages hook: one-commit CI checkout cannot establish complete history; no workflow changes authorized.
