- The pages are marketing pages. They name products and industries readily and name a plant process rarely: where a process is stated it is as an equipment maker's or tool maker's service ("dies, gear-cutting tools, and molds"), a parent's technology claim ("our proprietary technology produces polymers"), or a shop's about page (MSB). Plant-level "we injection mold…" sentences did not appear in 18 readable organizations.
- A source for process would need to be **site-grain and operation-grain**: it has to name the establishment and the thing done there. Permits, inspections and registry filings do that and own-site marketing pages mostly do not; the 2026-11-18 permit canary (`tasks/pic18-permit-canary-2026-11-18`) is the sibling route. I did not test any other source.
- Readability is a second limit: 7 of 25 gave nothing readable to this client, and 4 of the 7 failed on a robots/TLS/connection condition, not on page content. A failed fetch is availability, never absence.

## Method as run
`fetch.py`: record website, then up to 5 same-registrable-domain pages chosen from the **home page's** links by link text/path (capabilities, process, what we do/manufacturing, services, industries/markets/applications, products/solutions, about, in that order), direct curl (no proxy, no sitemap guess), robots.txt per host gated every hop, 1.2 s between requests per host, one retry only after a curl transport failure, no retry on any HTTP status. Captures (raw bytes, extracted main text with line kinds, sha256) are in `S/persist/web-canary-2026-11-22/`, outside the repo. Main text = visible text minus nav, header, footer, aside, form, script and menu-like class wrappers (with a tag-only fallback when a wrapper swallowed everything; flagged in `note`).
Deviations, stated plainly:
- **Pass 2:** the first run did not follow redirects when reading robots.txt, so 5 organizations showed ROBOTS_UNREADABLE for a defect of mine; fixed and re-run (their pass-1 rows stay in `fetches.csv`, labelled pass 1). Two of the 5 are still unavailable on the corrected run (timeout; robots disallow).
- **Pass 3:** CF Extrusion's home page is a meta-refresh to `/site/` on the same domain; the target is a link found on a fetched page, so it was fetched (and up to 5 links from it).
- robots.txt bodies were hashed, not stored (`check.py` exempts them); page captures are all stored. A few pages (e.g. AlphaMicron industries) were fetched under two URLs and are the same text.
- JavaScript was not executed, so script-rendered pages (SKF) are unreadable by construction.

## What a cheaper model could do, and what needs judgement
- **Cheaper-model steps, no loss:** frame draw (`frame.py`), fetching and storing (`fetch.py`), text extraction, the keyword screen (`screen.py`), offsets and hashes (`build_candidates.py`, `check.py`). These were about 40% of the effort and are deterministic; the fetch run needed two code fixes caused by my own defects (robots redirect, meta refresh), which a tested fetcher would have avoided.
- **Needs judgement:** deciding whether a sentence is the company's own claim at this organization's grain (parent page vs own, equipment maker vs processor, distributor vs fabricator); mapping words to the controlled vocabulary (polymerization, mold_tool_making, plastics_rubber_processors); deciding what to exclude from the frame. A cheaper model would likely over-fill from list items and parent pages; a screen-only run would have missed MSB's about page (the 2B lane screened this organization and found nothing).
